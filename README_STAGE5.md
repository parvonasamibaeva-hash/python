## Автоматическая проверка

Для этапов 9–14 тестовый запуск предварительно проверяет, можно ли детерминированно подменить `random.randint`. Затем код запускается с заданными значениями случайного числа и очередями `input()`. Неверные границы `randint` дают специальное контрольное значение, а стенд отдельно записывает количество вызовов и переданные границы — это не позволяет принять статический вывод без вызова генератора. Проверка сопоставляет вывод с каждым вводом по сегментам между вызовами `input()`, поэтому подсказка должна соответствовать конкретному предположению. Для проверки базы использованы два разных секрета; проверяются победа с первой попытки, направления «больше/меньше», победа на последней попытке, проигрыш, повторная игра, регистр, диапазоны сложности и «горячо/холодно». Подмена `random.randint` и `time.time` действует только во время теста; исходные функции восстанавливаются в `finally`, чтобы не загрязнять последующие запуски ученика.

Для этапа 14 отдельно проверяются `import time` и `time.time()`, а также возможность управлять тестовыми значениями времени. Если это недоступно в текущей среде Skulpt, проверка переводит решение на ручной путь. Ограничение времени на `input()` не реализовано.

Для этапа 15 автоматически проверяются последовательности двоичного поиска для целей 73, 1 и 100; ответы в верхнем регистре также проверяются. Контролируется не только порядок догадок, но и то, что каждая следующая догадка появляется после соответствующего ответа и что нет лишних догадок. Даже после успешной проверки поведения задача отправляется преподавателю для оценки объяснения алгоритма.
